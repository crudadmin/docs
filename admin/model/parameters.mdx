Every admin model is built from parameters that define how the administration, the database and the forms are generated. A freshly created model already contains the most common ones, which you can edit, remove or extend.

<Warning>
  Any parameter that creates a database column, or changes an existing column, requires `php artisan admin:migrate`. See [migrations](/admin/model/migrations).
</Warning>

## Fields
{/* feature: model.fields() */}

Fields are returned from the `fields()` method. The method receives the edited record, so rules can depend on it.

```php app/Models/Customer.php
public function fields($row = null)
{
    return [
        'username' => 'name:Full name|required',
        'email' => 'name:E-mail|email|required|unique:customers,email,'.($row?->getKey() ?? 'NULL'),
        'password' => 'name:Password|type:password'.($row ? '' : '|required'),
    ];
}
```

`$row` is `null` when a record is created, and the edited record when it is updated in the administration, in `getValidationRules($row)` and in `validateRequest()` called on a record. Fields resolved for a record do not change the fields returned later without a record.

The complete field reference is in [Fields](/admin/model/fields).

## Basic parameters

### Module name
{/* feature: model.name */}

The name of the module in the sidebar, in the module header and in the change history.

```php app/Models/Article.php
protected $name = 'Articles';
```

The value can also be a translation key, it is translated with `trans()`.

```php
protected $name = 'admin.models.articles';
```

When the name depends on runtime state, leave the property empty and define a `name()` method instead.

```php
public function name()
{
    return _('Articles');
}
```

<Warning>
  `$this->name` inside the model returns this property, not the `name` column. Use `$this->getAttribute('name')` in model methods when the table has a `name` column. The same applies to `$title`.
</Warning>

### Module description
{/* feature: model.title */}

Optional description shown under the module name. Translation keys are translated with `trans()`.

```php
protected $title = 'Edit the list of articles in the blog section.';
```

<Frame>
  <img src="/images/article-modeltitle.png" alt="Module description under the section heading" />
</Frame>

### Module icon
{/* feature: model.icon */}

Font Awesome icon of the module in the sidebar.

```php
protected $icon = 'fa-truck';
```

<Info>
  Without `$icon`, well known table names get an icon automatically, e.g. a table ending with `articles` gets `fa-file-alt`, `orders` gets `fa-credit-card`.
</Info>

### Disabling the module
{/* feature: model.active */}

Set `$active` to `false` to hide the module from the menu. The table is still migrated, and the module offers no permissions in user groups.

```php
protected $active = false;
```

The value can be decided on every request with a method:

```php
public function active($row = null)
{
    return config('shop.gift_cards.enabled');
}
```

<Warning>
  An inactive module is only hidden. Restrict access with [user group permissions](/admin/model/permissions) when needed.
</Warning>

## Dynamic parameters
{/* feature: model.property-resolution */}

Callable parameters can be declared as methods. The method wins over the property and is evaluated when the value is needed.

```php
public function insertable($row = null)
{
    return admin()?->hasAccess(static::class, 'import') === false;
}
```

A `set{Property}Property()` mutator changes the resolved value. It can be declared on the model, in a parent class or in a [model module](/admin/model/rules-events#modules). Model mutators run first, module mutators receive their result.

```php
public function setEditableProperty($editable)
{
    return $editable && ! $this->isClosedPeriod();
}
```

These parameters are resolved this way: `name`, `group`, `fields`, `active`, `inMenu`, `single`, `options`, `searches`, `insertable`, `editable`, `publishable`, `deletable`, `rules`, `settings`, `buttons`, `exports`, `reserved`, `layouts` and `belongsToModel`.

<Warning>
  Other parameters, for example `$displayable` or `$sortable`, are read from the property only. A `displayable()` or `sortable()` method is ignored.
</Warning>

## Cached queries
{/* feature: model.flushableCacheKeys, model.getCached(), model.runCached() */}

Cache small, rarely changed tables (countries, VAT rates, settings) and flush them automatically when a record is saved, deleted or reordered in the administration.

```php app/Models/Country.php
protected $flushableCacheKeys = ['countries', 'settings'];
```

```php
// Rows are cached for a week by default and returned as models
$countries = Country::where('active', true)->getCached('countries');

// First row or false
$country = Country::where('code', 'sk')->firstCached('settings', now()->addHour());

// Any value, the duration argument is optional
$settings = (new Store)->runCached('settings', fn () => Store::first());
```

Keys are stored as `models.{table}.{key}`. Mass updates through the query builder (`Country::query()->update([...])`) do not flush the cache.

## Replicating records
{/* feature: model.replicateWithRelations(), model.replicate() */}

`replicateWithRelations()` creates a copy of the record including many to many relations and all records of child models. It is typically used in a [button](/admin/model/actions).

```php app/Admin/Buttons/ReplicateCourse.php
public function fire(AdminModel $row)
{
    $row->replicateWithRelations([
        'except' => [CoursesStage::class],
    ]);

    return $this->message(_('Course has been replicated.'));
}
```

| Option | Description |
| --- | --- |
| `only` | clone only these child models |
| `except` | skip these child models |
| `unpublish` | `false` keeps the publication date of the cloned records, by default the copies are unpublished |

Single files are copied with the `cloned_xxxx_` prefix, multiple file fields keep references to the same files.

`replicate()` of admin models skips the `_order` column, so the copy gets a new position.

## Site tree
{/* feature: model.sitetree */}

With the [site tree module](/admin/configuration#optional-modules) enabled, records of a model can be linked in the site tree editor. The value is the label column.

```php app/Models/Branch.php
protected $sitetree = 'name';

public function scopeOnSiteTreeLoad($query)
{
    $query->where('visible', true);
}

public function getTreeAction()
{
    return action([BranchController::class, 'show'], $this->slug);
}
```
