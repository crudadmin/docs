Fields are the core of an admin model. Each field describes a database column, its form input, its validation rules, its relations and how it is shown in the listing table.

<Warning>
  The database follows the fields. Run `php artisan admin:migrate` after every change, see [changing fields](/admin/model/fields/database#changing-fields).
</Warning>

## Writing fields

Return the fields from the `fields()` method of the admin model. Each key is the name of a database column, the value is the field configuration combined with [Laravel validation rules](https://laravel.com/docs/master/validation#available-validation-rules).

The configuration is written as a string of parameters separated by `|`, or as an array.

### String notation
{/* feature: field.string-notation */}

This notation is recommended for all fields.

```php app/Models/Product.php
public function fields()
{
    return [
        'name' => 'name:Name|placeholder:Enter the product name|required|max:90',
        'opens_at' => 'name:Opening time|type:time|title:Shop opens at 10:00',
        'content' => 'name:Description|type:editor',
        'image' => 'name:Image|image|required',
    ];
}
```

Parsing rules:

- A parameter without a value is a flag and becomes `true`, `required` is `required => true`.
- Values are always strings, `default:10` becomes `'10'`.
- Only the first colon separates the key, so `title:Opens at 10:30` or `date_format:H:i` keep the rest of the value.
- A repeated parameter becomes an array of values, `index:a|index:b` is `index => ['a', 'b']`.
- Empty parts are ignored (`name:Name||required`), `placeholder:` sets an empty string.
- A value can not contain `|`. Use the array notation when you need it.

### Array notation
{/* feature: field.array-notation */}

Each field can also be an array. Values keep their PHP types, and a value without a key is a flag.

```php
public function fields()
{
    return [
        'title' => [
            'name' => 'Title',
            'required',          // same as 'required' => true
            'max' => 100,
        ],
        'stock' => [
            'name' => 'Stock',
            'type' => 'integer',
            'default' => 0,
            'required' => false,
        ],
        'note' => [
            'name' => 'Note',
            'title' => 'Separate values with | or :',
        ],
    ];
}
```

<Warning>
  Use real booleans. `'required' => 'true'` is a string, it is passed to Laravel validation but the column stays nullable.
</Warning>

### Method notation

Validation often differs between creating a record and editing it. The `fields()` method receives the edited record as `$row`, which is `null` in the create form.

Combine the string notation with arrays when you need [Laravel rule objects](https://laravel.com/docs/master/validation#custom-validation-rules).

```php
use Illuminate\Validation\Rule;

public function fields($row = null)
{
    return [
        'username' => 'name:Full name|required|max:30',
        'email' => 'name:E-mail|email|required|unique:users,email,'.($row?->getKey() ?: 'NULL'),
        'password' => 'name:Password|type:password|confirmed|min:8'.($row ? '' : '|required'),
        'nickname' => [
            'name' => 'Nickname',
            'required' => ! $row,
            Rule::unique('users')->ignore($row?->getKey()),
        ],
    ];
}
```

### Field keys
{/* feature: field.key-slug */}

The field key is the database column name. Keys are slugged with `_` as the separator, so they are also lowercased:

| Key in `fields()` | Column and request key |
| --- | --- |
| `firstName` | `firstname` |
| `last name` | `last_name` |
| `_internal` | `_internal` |

Always use snake_case keys. The original camelCase key is not recognised in requests, in `getField()` or as `$row->firstName`.

## Field parameters

Every parameter which is not an admin parameter is passed to the Laravel validator as a rule, see [validation rules](/admin/model/fields/validation). The admin parameters are documented on these pages:

| Page | Parameters |
| --- | --- |
| [Field types](/admin/model/fields/types) | `type`, `imaginary` |
| [Select options](/admin/model/fields/select-options) | `options`, `option`, `multiple`, `enum`, `defaultByOption`, `unique_options` |
| [Relation fields](/admin/model/fields/relations) | `belongsTo`, `belongsToMany`, `migrateToPivot`, `async`, `filterBy`, `fillBy`, `canAdd`, `canEdit`, `canView`, `canList`, `hasAccessFilter`, `required_with_values` |
| [Dates and times](/admin/model/fields/dates) | `date_format`, `date_step`, `default:CURRENT_TIMESTAMP`, `multiple` |
| [File uploads](/admin/model/fields/uploads) | `image`, `multiple`, `multirows`, `private`, `resize` |
| [Validation rules](/admin/model/fields/validation) | `required`, `null`, `max`, `min`, `unsigned`, `confirmed`, `extensions`, `unique_json`, `required_if`, `sometimes` |
| [Visibility and access](/admin/model/fields/visibility) | `hidden`, `invisible`, `inaccessible`, `inaccessible_column`, `hideFromForm`, `removeFromForm`, `hideOnCreate`, `hideOnUpdate`, `readonly`, `disabled`, `keepInRequest`, `hasAccess`, `hasNotAccess`, `inAdmin`, `inFrontend`, `inConsole` |
| [Labels and listing](/admin/model/fields/ui) | `name`, `title`, `placeholder`, `tooltip`, `counter`, `editor_height`, `column_name`, `limit`, `orderBy`, `column_visible`, `column_present`, `column_editable`, `unsearchable`, `phone_link` |
| [Custom components](/admin/model/fields/components) | `component`, `sub_component`, `column_component` |
| [Translatable fields](/admin/model/fields/localization) | `locale` |
| [Database columns](/admin/model/fields/database) | `index`, `unique_index`, `fulltext`, `default`, `decimal_length`, `encrypted` |

Fields can be arranged into groups and tabs, and fields of an existing model can be changed with `mutateFields()`, see [groups and tabs](/admin/model/fields/groups).
