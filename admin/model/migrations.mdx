## Running migrations
{/* feature: command.admin:migrate */}

```bash
php artisan admin:migrate
```

The command compares every admin model with the last migrated state. Unchanged models are skipped (`Nothing to migrate.`), changed ones print `Created table` or `Updated table`.

| Option | Description |
| --- | --- |
| `--force`, `-f` | Migrate all models, even unchanged ones. |
| `--auto-drop` | Drop unknown columns without asking. |
| `--unknown`, `-u` | With `--force`, list tables that do not belong to any admin model and ask to drop each of them. |

When a column exists in the table but not in the fields, the command prints `+ Unknown column: name` and asks whether to drop it. Use [`$skipDropping`](#skipping-column-removal) for columns managed elsewhere.

## Creation date
{/* feature: model.migration_date */}

`$migration_date` orders admin models in migrations and in the menu. Parent models, and models referenced by `belongsTo`, must have an earlier date than their children.

```php
protected $migration_date = '2026-01-10 10:00:00';
```

<Info>
  Required parameter, generated by `admin:model`. A model without a migration date is not registered as an admin model, and two models with the same date stop the application with an error naming both models.
</Info>

## Automatic columns
{/* feature: model.staticColumns */}

Columns are added after the field columns in this order:

| Column | Added when |
| --- | --- |
| `language_id` | [`$localization = true`](/admin/model/localization#unique-records-per-language), foreign key to `languages` |
| `_order` | the model is [sortable](/admin/model/tree#reordering-records) (default), indexed |
| `slug` | [`$sluggable`](/admin/frontend/sluggable) is set |
| `published_at` | the model is [publishable](/admin/model/tree#publishing-records) (default), indexed |
| `created_at`, `updated_at` | `$timestamps` (default) |
| `deleted_at` | `$timestamps` (default), indexed, soft deletes |

```php
protected $sortable = false;
protected $publishable = false;
public $timestamps = false;
```

## Timestamps and soft deletes
{/* feature: model.timestamps, model.hasSoftDeletes() */}

Admin models with timestamps use soft deletes. Deleted records stay in the table and are hidden in the administration and in queries, `withTrashed()` shows them.

```php
// No created_at, updated_at and deleted_at columns, records are deleted permanently
public $timestamps = false;

// Keep created_at and deleted_at, skip updated_at
const UPDATED_AT = null;
```

A `deleted_at` field enables soft deletes without timestamps:

```php
public $timestamps = false;

public function fields()
{
    return [
        'name' => 'name:Name|required',
        'deleted_at' => 'name:Deleted at|type:datetime|invisible',
    ];
}
```

Remove a soft deletable record permanently with the [`force` delete option](/admin/model/permissions#delete-options).

## Table and connection
{/* feature: model.table, model.connection, model.skipMigration */}

Standard Eloquent properties are respected by migrations:

```php
protected $table = 'shop_products';   // table created by admin:migrate and used in admin requests

protected $connection = 'warehouse';  // the table is migrated on this connection
```

A model without a table, e.g. a dashboard built from [layouts](/admin/model/layouts), skips migrations:

```php
protected $skipMigration = true;
```

## Skipping column removal
{/* feature: model.skipDropping */}

Columns that exist in the table but are not defined in fields are offered for dropping. List columns managed outside of the admin model to keep them without asking, e.g. in a table shared with another project:

```php
protected $skipDropping = ['external_id', 'legacy_code'];
```

Columns can also be added at runtime, e.g. from a migration hook:

```php
public function beforeMigrate(Blueprint $table, $schema, $command)
{
    $this->addSkipDroppingColumn('imported_at');
}
```

## Migration hooks
{/* feature: model.beforeMigrate(), model.onTableCreate(), model.afterMigrate(), model.onMigrateEnd() */}

Hooks receive the `Blueprint` of the model table, the schema builder and the running command. Changes made on the blueprint are executed.

```php
use Illuminate\Database\Schema\Blueprint;

// Before the table is created or updated
public function beforeMigrate(Blueprint $table, $schema, $command) {}

// Only once, right after the table is created
public function onTableCreate(Blueprint $table, $schema, $command)
{
    $this->create(['name' => 'Main warehouse']);
}

// After every create or update of the table
public function afterMigrate(Blueprint $table, $schema, $command)
{
    if ( ! $schema->hasIndex($this->getTable(), ['code'], 'unique') ) {
        $table->unique('code');
    }
}

// After all admin models have been migrated
public function onMigrateEnd(Blueprint $table, $schema, $command) {}
```

<Note>
  Hooks run only when the model is migrated. Without changes in the model use `php artisan admin:migrate --force`.
</Note>

Hooks for a missing parent id of existing rows are described in [tree structured models](/admin/model/tree#tree-structured-models), migration events for packages in [helpers](/admin/helpers#migration-events).
