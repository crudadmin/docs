This page covers the localization settings in `config/admin.php` and how to use them.

## Enabling localization
{/* feature: config.localization */}
{/* feature: helper.Admin::isEnabledLocalization */}

If the application needs multiple language versions, switch the parameter to `true`. Then run the database migration, which creates the `languages` table and adds the language management module to the administration.

```php config/admin.php
'localization' => true,
```

<Note>
  The first language added in the administration becomes the default one.
</Note>

<Warning>
  Run `php artisan admin:migrate` after enabling localization.
</Warning>

### Forced redirect to the default language

<Note>
  Language prefixes in urls, the redirects and the helpers below: available with the `crudadmin/website` package (`composer require crudadmin/website`).
</Note>

To redirect to the default language version automatically, add the middleware in `bootstrap/app.php`.

```php bootstrap/app.php
use AdminWebsite\Middleware\LocalizationMiddleware;
use Illuminate\Foundation\Configuration\Middleware;

->withMiddleware(function (Middleware $middleware) {
    $middleware->append(LocalizationMiddleware::class);
})
```

The client is redirected to the default language version on arrival — `http://example.com/` redirects to `http://example.com/sk`.

With localization active, **every route** is redirected to the address carrying the language code — `http://example.com/articles` redirects to `http://example.com/sk/articles`.

### Disabling the forced redirect
{/* feature: config.localization_remove_default */}

The forced redirect can be turned off. On the default language version, every URL is then available without the language code.

```php config/admin.php
'localization_remove_default' => true,
```

<Info>
  With this parameter, content on the default language is available only without the language code — `http://example.com/articles` instead of `http://example.com/sk/articles`. A different language saved in the session still redirects to its prefix.
</Info>

### Localized routes and URLs
{/* feature: helper.localizedRoutes, helper.localeUrl, helper.switchLocale */}

`localizedRoutes()` registers a routes file with the language prefix, so `/articles` is available as `/en/articles` too.

```php bootstrap/app.php
use Illuminate\Support\Facades\Route;

->withRouting(
    using: function () {
        Route::middleware('web')->group(localizedRoutes('routes/web.php'));
    },
)
```

```blade
<a href="{{ localeUrl('articles') }}">Articles</a>          {{-- /en/articles --}}
<a href="{{ switchLocale($language) }}">{{ $language->name }}</a> {{-- current URL with ?_locale=de --}}
```

### Administration language
{/* feature: config.locale, config.admin_localization */}
{/* feature: helper.Admin::isEnabledAdminLocalization */}

```php config/admin.php
'locale' => 'en',              // default language of the administration (en, sk, cs)
'admin_localization' => true,  // administrators can switch the administration language
```

`Admin::isEnabledLocalization()` and `Admin::isEnabledAdminLocalization()` return the state of both switches.

## Gettext — translating static texts

Together with the Gettext extension, CrudAdmin collects every static source text in the application and makes it translatable as *.po* files for [PoEdit](https://poedit.net/), or through the online editor in the administration.

### Enabling Gettext
{/* feature: config.gettext */}

Enable the extension in `config/admin.php`.

```php config/admin.php
'gettext' => true,
```

<Note>
  The `@gettext` directive: available with the `crudadmin/website` package (`composer require crudadmin/website`).
</Note>

To translate in JavaScript and Vue components on the frontend, add the library that initialises the translation functions. The `@gettext` blade directive handles it — place it in the main layout as the first script in the order. The system injects the translation libraries and caches them.

```blade resources/views/layout.blade.php
        @gettext

        @vite('resources/js/app.js')
    </body>
</html>
```

<Note>
  CrudAdmin scans the directories where translatable files may live and reloads every source text on change. The scanned paths are defined in [Gettext options](#gettext-options).
</Note>

<Warning>
  After enabling Gettext, run `php artisan admin:migrate` to add the columns to the language table and enable editing **PO** and **MO** files.
</Warning>

<Tip>
  The **.PO** file for translation is available for download in the administration.
</Tip>

### Writing translations in the application

For translations to be picked up, static texts have to be written in the right form. The examples below cover both singular and plural.

#### PHP files
{/* feature: helper._ */}

PHP files follow the standard functions from the [PHP documentation](http://php.net/manual/en/function.gettext.php).

```php
// Singular
echo _('This is my translate');

// Plural
$count = 2;
echo sprintf(ngettext('%d car', '%d cars', $count), $count);
```

#### Blade files

Blade files are translated the same way as plain PHP.

```blade
<div>{{ _('This is my translate') }}</div>
<div>{{ sprintf(ngettext('%d car', '%d cars', $count), $count) }}</div>
```

#### JavaScript files

CrudAdmin reads translations from JavaScript files as well, through the methods of the injected library.

```javascript
var a = _('This is my translate');
var b = __('This is my translate');
var c = gettext('This is my translate');

var d = n__('%d car', '%d cars', 2).replace('%d', 2);
var e = ngettext('%d car', '%d cars', 2).replace('%d', 2);

console.log(a, b, c, d, e);
```

#### Vue components

Vue components use the same JavaScript functions. They are bound into every component, so they are available globally as well as in the `this` constructor.

```html
<template>
    <div>{{ _('This is my translate') }}</div>
    <div>{{ n__('%d car', '%d cars', 2).replace('%d', 2) }}</div>
    <div>{{ myTranslate() }}</div>
</template>

<script>
export default {
    methods: {
        myTranslate()
        {
            var trans1 = __('I have'),
                trans2 = n__('%d car', '%d cars', 2).replace('%d', 2),
                trans3 = this._('and'),
                trans4 = ngettext('%d wheel', '%d wheels', 4).replace('%d', 4);

            return trans1 + ' ' + trans2 + ' ' + trans3 + ' ' + trans4;
        }
    }
}
</script>
```

### Gettext options
{/* feature: config.gettext_source_paths, config.gettext_admin_source_paths, config.gettext_supported_codes, config.gettext_json, config.gettext_remove_missing */}

```php config/admin.php
// Sources scanned for website translations, merged with the package defaults
// (routes, app/Http, app/Mail, app/Notifications, app/Models, resources/views, resources/js, ...)
'gettext_source_paths' => [
    'app/Services',
    'resources/views',
],

// Sources scanned for administration translations
'gettext_admin_source_paths' => ['app/Admin', 'app/Models'],

// Language slugs which can not be resolved to a gettext locale automatically
'gettext_supported_codes' => [
    'cz' => 'cs_CZ',
    'english' => 'en_GB',
],

// /vendor/js/ca-translates-json.js returns translations as JSON
'gettext_json' => true,

// Remove translations missing in sources instead of flagging them
'gettext_remove_missing' => true,
```

The language slug chosen in the administration is used in the URL, for example `example.com/cz`. Built-in codes resolve `sk` to `sk_SK` and `cz` to `cs_CZ`, five letter codes are used as they are. Register other slugs in `gettext_supported_codes` for translations to work.

## Translating dynamic content

Once language versions and static text translations are set up, the interface for translating the dynamic content stored in the database can be generated too.

### Mirrored content
{/* feature: field.locale */}

With mirrored content the record exists once in the database, and each translatable column holds a value for every language. Add the `locale` parameter to the fields you want to translate.

```php app/Models/Project.php
public function fields()
{
    return [
        'name' => 'name:Project title|locale|required',
        'content' => 'name:Content|type:editor|locale',
    ];
}
```

The column stores a JSON object keyed by the language slug. Reading the attribute returns the value of the current language, with a fallback to the default language.

#### Required translations
{/* feature: model.getDefaultLanguage() */}

Required rules of a `locale` field apply only to the default (first) language, other languages are optional. The model can choose another language, `null` uses the default one.

```php
public function getDefaultLanguage()
{
    return Language::where('slug', 'en')->first();
}
```

Fallbacks, validation, API responses and converting existing columns are described in [Translatable fields](/admin/model/fields/localization).

### Records owning a language
{/* feature: model.HasEntryLocales */}

Models like clients or notifications can remember the language of a record, e.g. to send e-mails in the language of the client. Declare a `language_id` field bound to `languages` and use the `HasEntryLocales` trait.

```php app/Models/Client.php
use Admin\Eloquent\Concerns\HasEntryLocales;

class Client extends AdminModel
{
    use HasEntryLocales;

    public function fields()
    {
        return [
            'name' => 'name:Name|required',
            'language_id' => 'name:Language|belongsTo:languages,name',
        ];
    }
}
```

```php
$client->addLocale();   // fills an empty language_id with the current language
$client->saveLocale();  // updates language_id to the current language

$client->getLocale();   // language of the record, or the first language

$client->withLocale(function () use ($client) {
    $client->notify(new OrderShipped);
});
```
