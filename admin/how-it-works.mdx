CrudAdmin reads **Eloquent** models that carry additional parameters. Once extended this way, we call them **Admin models**. From them CrudAdmin generates the whole administration interface, forms with automatic validation, and the complete database including relations.

Adding a new section to the administration takes three steps:

<Steps>
  <Step title="Create an admin model">
    ```bash
    php artisan admin:model Article
    ```
  </Step>
  <Step title="Migrate the database">
    ```bash
    php artisan admin:migrate
    ```
  </Step>
  <Step title="Done">
    A fully working administration section is live.
  </Step>
</Steps>

## Database design

The database and its relations are designed from the fields defined in the **admin model**.

When a model carries parameters that describe a relationship with other models, CrudAdmin creates the relations in the database and connects the generated forms in the interface. Every relation type is supported. The example below shows a **one to many** relation.

### 1. Linking admin models through a relation

This example links two admin models with the [belongsToModel](/admin/model/tree#tree-structured-models) property. Once linked, opening the parent record shows a nested section for the related model.

  <img src="/images/preview/article-relationship-model.png" alt="Two admin models linked with belongsToModel" />

### 2. Migrating the database

Any change in the **admin model** that is represented by a database column has to be migrated with an `artisan` command.

<Frame>
  <img src="/images/terminal/article-migration.png" alt="Output of the php artisan admin:migrate command" />
</Frame>

### 3. Generated tables and relations

From the fields in the admin model, CrudAdmin created the database tables, set the column types and built the relations between them.

<Frame>
  <img src="/images/database/article-relationship-diagram.png" alt="Database diagram of the generated tables and their relation" />
</Frame>

<Note>
  When you add new fields to an existing table, CrudAdmin adds the columns automatically — you do not write migrations.
</Note>

<Warning>
  When you remove a field that still exists as a database column, CrudAdmin asks you to confirm dropping the column during the migration.
</Warning>

<Info>
  Depending on the admin model configuration, CrudAdmin adds extra columns such as the language, record position, slug, publication date and timestamps (`language_id`, `_order`, `slug`, `published_at`, `created_at`, `updated_at`, `deleted_at`). See [automatic columns](/admin/model/migrations#automatic-columns).
</Info>
