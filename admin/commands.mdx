## Installation and updates
{/* feature: command.admin:account */}
{/* feature: command.editor:ckeditor:download, command.editor:ckfinder:download */}

| Command | Description |
| --- | --- |
| `admin:install` | Publishes the config and assets, runs migrations and creates the `admin@admin.com` demo account. Safe to run again, an existing demo account is kept. |
| `admin:update` | Replaces published admin assets with the installed version. Run it after `composer update crudadmin/*`. |
| `admin:account` | Creates another administrator, asks for the username, e-mail and password. |
| `editor:ckeditor:download` | Downloads CKEditor, skipped when installed (use `--force`). |
| `editor:ckfinder:download` | Downloads the CKFinder connector for the [file browser](/admin/configuration#file-browser). |

## Migrations
{/* feature: command.admin:encrypt-existing */}

| Command | Description |
| --- | --- |
| `admin:migrate` | Creates and updates the tables of all admin models, see [Migrations](/admin/model/migrations). |
| `admin:encrypt-existing` | Encrypts existing plain values of [`encrypted`](/admin/model/fields/database#encrypted-values) fields in all admin models. |

### Encrypting existing values

Adding `encrypted` to a field with stored data leaves the existing rows as plain text. Run the command after `admin:migrate` to encrypt them:

```bash
php artisan admin:encrypt-existing --dry-run
php artisan admin:encrypt-existing
php artisan admin:encrypt-existing --model=clients --model='App\Models\Company'
```

- `--dry-run` counts the rows with plain values per table, nothing is written.
- `--model` accepts a table, a full class name or a class name without namespace, and can be repeated. Without it, every admin model with an encrypted field is processed.
- `--chunk` sets how many rows are loaded at once, `500` by default.

Values that are already encrypted are skipped, so the command can be run again. Search hashes of the encrypted fields are filled in `_encrypted_hashes` too. The values are written straight into the table: model events, rules, history and `updated_at` are not touched. Back up the database first, a value encrypted with a wrong `APP_KEY` can not be read back.

## Model settings migration
{/* feature: command.admin:upgrade:settings */}

Convert settings of older major versions in application models and move the supported literal ones into the editor map:

```bash
php artisan admin:upgrade:settings --dry-run
php artisan admin:upgrade:settings
php artisan admin:upgrade:settings --model='App\Models\Product' --dry-run
```

The command handles `$settings`, straight-line `settings()` methods and `setSettingsProperty()` mutators. It renames the settings of the [v6 upgrade](/admin/upgrade-guide/v6) in place, drops the removed ones, collapses the old grid keys into a single `grid.sizes` list, converts `before`/`after` ordering on field columns to a visibility and order snapshot, and removes only successfully migrated entries. Existing overrides take precedence. Run it in a development working tree, review the diff and commit both the model edits and `bootstrap/admin.php`.

Dynamic expressions and conditional methods are reported and left unchanged for manual migration, and so is a rename whose target setting is already declared or whose nesting cannot hold the new name. The command rewrites only registered models whose source files are inside the application's `app/` directory; it does not rewrite installed or linked package sources. `--model` accepts a full class name or an admin table and can be repeated. `--dry-run` reports prospective changes without writing files. Production execution is refused.

## Config migration
{/* feature: command.admin:upgrade:config */}

Move the config keys grouped in CrudAdmin 6 under their new groups in `config/admin.php`:

```bash
php artisan admin:upgrade:config --dry-run
php artisan admin:upgrade:config
```

The command moves every declaration as it is written, so comments, `env()` calls and closures survive the move, and it deletes the keys which no longer do anything. It reports what it cannot convert: a key whose new path is already declared, and two old keys of one new key holding different values. `--path` migrates another config file than `config/admin.php`, for example the `src/Config/admin.php` of a package. The full list of moved keys is in the [v6 upgrade guide](/admin/upgrade-guide/v6#config-keys-grouped).

Outside production the administration throws on boot while an old key is still declared, so run the command before starting the application. The command itself is never blocked by that check.

## Performance cache
{/* feature: command.admin:cache, command.admin:clear */}

| Command | Description |
| --- | --- |
| `admin:cache` | Compiles the complete map of admin models, their tables, autoloaded modules, base fields and relations into `bootstrap/cache/crudadmin.php`. |
| `admin:clear` | Removes the compiled file, models are discovered and built at runtime again. |

Without the cache every request scans the model directories, constructs each model and builds its fields and relations. Packages register their models one by one while service providers boot, so this work is repeated several times per request. With the cache the whole models set is known from the very first moment and regular requests build nothing.

`admin:cache` boots the application in a fresh process, registers all models exactly as a request does and constructs them repeatedly until no new model appears. Compiled base fields and relations are used on frontend and API requests only. The administration, migrations and fields of a given row (`getFields($row)`) are always built at runtime, because they depend on the logged administrator or on the row itself.

The cache is part of `php artisan optimize` and `optimize:clear`, `admin:migrate` refreshes it when it exists, and `admin:update` compiles it in production or with `APP_DEBUG=false`. In debug mode a change of any model directory disables the compiled file until it is compiled again.

<Warning>
  Compiled fields are bound to the default language and to translations of field names. Run `admin:cache` after changing the default language or the translations of `name`, `title` and `placeholder` attributes.
</Warning>

## Generators
{/* feature: command.admin:export, command.admin:statistics, command.admin:component */}

Subdirectories in the name become namespaces, e.g. `admin:button Orders/SendInvoice` creates `App\Admin\Buttons\Orders\SendInvoice`. Existing files are never overwritten.

| Command | Creates |
| --- | --- |
| `admin:model Name` | [admin model](/admin/model/index#creating-an-admin-model) |
| `admin:button Name` | [button](/admin/model/actions#creating-a-button) in `app/Admin/Buttons` |
| `admin:rule Name` | [admin rule](/admin/model/rules-events#admin-rules) in `app/Admin/Rules` |
| `admin:module Name` | [model module](/admin/model/rules-events#modules) in `app/Admin/Modules` |
| `admin:layout Name` | [layout](/admin/model/layouts#creating-a-layout) in `app/Admin/Layouts` with a Vue component or Blade view |
| `admin:component Name` | Vue component in `resources/views/admin/components/{fields,layouts,buttons,columns}/Name.vue` |
| `admin:request Name` | [form request](/admin/validation/request) in `app/Http/Requests` |
| `admin:export Name` | [export](/admin/model/listing#exports) in `app/Admin/Exports` |
| `admin:statistics Name` | statistics class in `app/Admin/Statistics` |

## Pre-resize images
{/* feature: command.admin:preresize */}

```bash
php artisan admin:preresize
```

- Choose a model, a file field, and the target width and height. Leave one dimension blank to preserve the aspect ratio; two dimensions crop to fit.
- Reads the field's configured storage, including subdirectories, and prepares images in the standard resize cache immediately. Existing cached sizes are reused; originals are unchanged.
- Processes JPG, JPEG, PNG, GIF, BMP and WebP files. Other files, including SVG, are skipped.
- Prints a summary of ready, skipped and failed images. A failed image does not stop the remaining files; any failures produce a nonzero exit code.

## Upgrade commands live in a separate package

The migrators which move a project onto this major version ship in `crudadmin/upgrade`, a development dependency. Install it for the upgrade and remove it afterwards, it adds nothing to a running application.

```bash
composer require --dev crudadmin/upgrade:^6.0
```

`php artisan admin:upgrade` runs every step in order: `admin:upgrade:config`, `admin:upgrade:settings`, `admin:upgrade:icons`, `admin:upgrade:navigation`, `admin:upgrade:dates` and `admin:upgrade:cache`. Each step also runs on its own and every one takes `--dry-run`. `admin:upgrade:cache` writes nothing, it lists the closures in config files and the `env()` calls outside them, which break `php artisan optimize`, and fails while any is left. Do not confuse them with `admin:migrate`, which builds the database schema from the models and stays in the core.
