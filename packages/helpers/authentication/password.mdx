---
title: "Password reset"
description: "Reset links and links setting the first password, for users and e-shop clients."
---

`AdminAuth::password()` registers two routes. The e-mail contains a link of your client application, which sends the token back with the new password.

```php routes/api.php
AdminAuth::password();
```

```php config/admin_helpers.php
'auth' => [
    'password' => [
        'broker' => null, // the user provider of the guard by default
        'reset_url' => env('AUTH_PASSWORD_RESET_URL'), // e.g. https://shop.sk/heslo?token={token}&email={email}
        'expire' => 60, // minutes, for a broker missing in auth.passwords
    ],
],
```

A missing `auth.passwords` entry of the provider is created with the `password_reset_tokens` table. Use the `AdminHelpers\Auth\Concerns\HasPasswordResetLink` trait in the model, so the CrudAdmin reset e-mail links to `reset_url` instead of the administration, or define `getResetLink($token)` yourself.

## Sending the link

`POST auth/password/forgot` with `email`. The answer is the same success message whether the account exists or not. Throttled like OTP codes.

## Setting the password

`POST auth/password/reset` with `token`, `email`, `password` and `password_confirmation`. The password is saved, the e-mail is marked as verified and the user is signed in: the response is the [login response](/packages/helpers/authentication/login#login-response) with a token named `password`. An invalid or expired token answers `422`.

Override `passwordRules()` in your controller (extend `AdminHelpers\Auth\Controllers\PasswordController`) to change the validation. Keep the maximum below 60 characters: CrudAdmin stores a 60 characters value as an existing hash.

## Link to set the first password

Accounts created without a password, e.g. during an order, get a link instead of a random password:

```php
use AdminHelpers\Auth\Utilities\PasswordReset;

PasswordReset::sendSetPasswordLink($client); // guard of admin_helpers.auth.guard
PasswordReset::sendSetPasswordLink($client, 'api');
```

It sends `AdminHelpers\Auth\Notifications\SetPasswordNotification`. The client app uses the same `auth/password/reset` route. `PasswordReset::broker($guard)` and `PasswordReset::url($user, $token)` are available for custom notifications.
